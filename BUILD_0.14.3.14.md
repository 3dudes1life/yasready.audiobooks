# YasReady Audiobooks 0.14.3.14 — Production Arm & Chapter One Pilot

0.14.3.14 is the first bounded production release. It does **not** arm the full book.

## What it adds

- accepts the immutable 0.14.3.13 Production Plan & Budget as a legacy planning artifact while continuing to verify its digest
- new 0.14.3.14 production plans exclude print-only `Front Matter` from paid narration workload
- rebuilds Chapter One text from the exact manuscript and verifies every planned text/generation digest before production
- skips Front Matter and requires exactly one narrative `Chapter 1`
- performs a live ElevenLabs subscription/quota check with `character_count` and `character_limit`
- never invents provider credits from dollars or character counts
- verifies ElevenLabs + FFmpeg health before creating a pilot arm
- creates a new `PILOT-...` spend token; the old `PLAN-...` token is explicitly rejected as spend authorization
- sets the pilot hard ceiling equal to the displayed protected max
- renders only Chapter One with Ryan's locked provider settings (`speed 1.20`, `stability 0.24`)
- applies pitch-preserving FFmpeg `atempo=1.041667` for effective 1.25 pace
- resumes stored paid chunks instead of buying them again
- marks unknown provider outcomes `DO NOT RERUN PROVIDER`
- treats local tempo failures as safe-to-rerun without repeating stored paid TTS
- assembles Chapter One locally, creates an ACX-profile pilot master, and runs local technical QA
- creates a local human review board with PASS / MAYBE / FAIL feedback export
- a human PASS validates only the pilot and still leaves full-book generation unarmed

## Commands

Zero-spend live preflight + pilot arm:

```bash
node src/cli.js production-pilot-arm \
  <book-one-production-plan.json> \
  <book_1.docx> \
  --out <pilot-arm-directory>
```

Explicitly approved Chapter One production:

```bash
node src/cli.js production-pilot-render \
  <chapter-one-pilot-arm.json> \
  --plan <book-one-production-plan.json> \
  --manuscript <book_1.docx> \
  --out <pilot-directory> \
  --approve-spend PILOT-XXXXXXXXXX \
  --max-usd <exact-protected-max>
```

After human review:

```bash
node src/cli.js production-pilot-finalize \
  <chapter-one-pilot-feedback.json> \
  --arm <chapter-one-pilot-arm.json> \
  --render <chapter-one-pilot-result.json> \
  --out <pilot-final-directory>
```

## Safety boundary

Chapter Two and later cannot be generated by this release's pilot command. There is no automatic scale-up path. Even a passed pilot leaves `productionArmed=false` and `fullBookGenerationArmed=false`.
